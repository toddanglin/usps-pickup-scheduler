# PickupBar — macOS menu bar utility for USPS Carrier Pickup

Date: 2026-09-18
Status: approved (user delegated design decisions)

## 1. Purpose

A small, native macOS menu bar app that schedules a free USPS Carrier Pickup in
a few clicks, using the USPS Carrier Pickup 3.0 API. It removes the daily
"re-login, wait for the address to load" friction of usps.com for people who
schedule pickups several times a week. It will be published as an open-source
repo (MIT).

## 2. Constraints discovered during research

- USPS APIs authenticate apps, not consumers. The supported flow for a desktop
  tool is **OAuth 2.0 client_credentials** using a Consumer Key/Secret the user
  creates at <https://developers.usps.com> (free, "Add App"). The USPS
  authorization-code flow is enterprise-only (its authorize endpoint needs a
  bearer token and a `user_id`), so there is no "Sign in with USPS" screen.
- Access tokens last ~8 h (`expires_in` ≈ 28799 s) and renew silently.
- Endpoints (production base `https://apis.usps.com`, test base
  `https://apis-tem.usps.com`):
  - `POST /oauth2/v3/token` — JSON body `{grant_type, client_id, client_secret}`
  - `GET  /pickup/v3/carrier-pickup/eligibility?streetAddress=&city=&state=&ZIPCode=`
  - `POST /pickup/v3/carrier-pickup` — schedule
- Pickups: Mon–Sat, no postal holidays, same-day allowed until 2:00 AM Central.
  Request flag `nextAvailablePickup: true` makes USPS roll forward if the date
  is unavailable.
- Package types: `FIRST-CLASS_PACKAGE_SERVICE` (shown as "Ground Advantage"),
  `PRIORITY_MAIL`, `PRIORITY_MAIL_EXPRESS`, `INTERNATIONAL`, `RETURNS`, `OTHER`.
- Pickup locations: `FRONT_DOOR`, `BACK_DOOR`, `SIDE_DOOR`, `KNOCK_ON_DOOR`,
  `MAIL_ROOM`, `OFFICE`, `RECEPTION`, `IN_AT_MAILBOX`, `SECURITY_DECK`,
  `SHIPPING_DOCK`, `OTHER`. Plus `specialInstructions` (string) and
  `dogPresent` (bool).
- There is **no hazmat field** in the API. Hazmat is a UI-only attestation.

## 4. Architecture

```
PickupBarApp (MenuBarExtra + Settings scene)
 └─ AppState (@MainActor ObservableObject)  ── flow state machine
      ├─ SettingsStore   (UserDefaults JSON)   – address, contact, defaults, env toggle
      ├─ KeychainStore   (Security.framework)  – client id/secret
      ├─ TokenManager    (actor)               – cached access token, refresh before expiry
      └─ USPSClient      (protocol + Live)     – token / eligibility / schedule
Views: RootView → Onboarding | AddressSetup | PickupForm | Scheduling | Confirmation | Error
Settings window: Account | Address | Defaults | General(launch at login, quit)
```

### 4.1 Flow state

```swift
enum FlowState: Equatable {
  case needsCredentials
  case needsAddress
  case form
  case scheduling
  case confirmed(PickupConfirmation)
  case failed(USPSError, retryable: Bool)
}
```

Transitions:
- launch → `needsCredentials` if Keychain empty; else `needsAddress` if no
  validated address; else `form`.
- Onboarding "Verify & Save" → fetch token; success → save creds → `needsAddress`
  or `form`; failure → inline error in onboarding (no state change).
- Address "Validate & Save" → eligibility; success → store standardized address
  → `form`; failure → inline error.
- Form "Schedule pickup" → `scheduling` → `confirmed` or `failed`.
- Confirmation "Schedule another pickup" → `form` (form keeps defaults, resets
  counts to defaults, reselects first day).
- Error "Try again" → `form` with previous draft retained.
- Credential invalid detected anywhere → `needsCredentials` + `needsAttention = true`.

### 4.2 Models (all `Codable`, `Sendable`)

```swift
enum PackageType: String, CaseIterable, Codable {
  case groundAdvantage = "FIRST-CLASS_PACKAGE_SERVICE"
  case priorityMail = "PRIORITY_MAIL"
  case priorityMailExpress = "PRIORITY_MAIL_EXPRESS"
  case international = "INTERNATIONAL"
  case returns = "RETURNS"
  case other = "OTHER"
  var displayName: String  // "Ground Advantage", "Priority Mail", "Priority Mail Express", "International", "Returns", "Other"
}

enum PackageLocation: String, CaseIterable, Codable {
  case frontDoor = "FRONT_DOOR", backDoor = "BACK_DOOR", sideDoor = "SIDE_DOOR",
       knockOnDoor = "KNOCK_ON_DOOR", mailRoom = "MAIL_ROOM", office = "OFFICE",
       reception = "RECEPTION", mailbox = "IN_AT_MAILBOX", securityDeck = "SECURITY_DECK",
       shippingDock = "SHIPPING_DOCK", other = "OTHER"
  var displayName: String  // "Front Door", "Back Door", "Side Door", "Knock on Door / Ring Bell", "Mail Room", "Office", "Reception", "In/At Mailbox", "Security Deck", "Shipping Dock", "Other"
}

struct PostalAddress: Codable, Equatable {
  var streetAddress: String
  var secondaryAddress: String?
  var city: String
  var state: String        // 2-letter
  var ZIPCode: String      // 5 digits
  var ZIPPlus4: String?
}

struct PickupContact: Codable, Equatable {
  var firstName: String
  var lastName: String
  var firm: String?
  var phone: String        // digits only, 10
  var email: String?
}

struct PickupAddress: Codable, Equatable {   // wire shape
  var firstName: String; var lastName: String; var firm: String?
  var address: PostalAddress
  var contact: [ContactEntry]   // [{"email":..},{"phone":..}] — custom encode/decode
}

struct PackageLine: Codable, Equatable { var packageType: PackageType; var packageCount: Int }
// packageCount decodes from Int OR String ("1") — USPS returns strings.

struct PickupLocation: Codable, Equatable {
  var packageLocation: PackageLocation
  var specialInstructions: String?
  var dogPresent: Bool
}

struct SchedulePickupRequest: Codable, Equatable {
  var pickupDate: String            // "yyyy-MM-dd"
  var pickupAddress: PickupAddress
  var packages: [PackageLine]       // only lines with count > 0
  var estimatedWeight: Double       // pounds
  var pickupLocation: PickupLocation
  var nextAvailablePickup: Bool
}

struct PickupConfirmation: Codable, Equatable {
  var confirmationNumber: String
  var pickupDate: String
}
// Decoded leniently: top-level confirmationNumber + pickupDate (both response shapes have these).

struct USPSErrorBody: Codable {   // { "apiVersion", "error": { "code", "message", "errors": [ {code,message,...} ] } }
  struct Detail: Codable { var code: String?; var message: String?; var title: String?; var detail: String? }
  struct Inner: Codable { var code: String?; var message: String?; var errors: [Detail]? }
  var apiVersion: String?; var error: Inner?
}
```

### 4.3 Errors

```swift
enum USPSError: Error, Equatable {
  case offline
  case invalidCredentials              // token 401 / invalid_client
  case forbidden                       // 403 on pickup — app lacks Pickup product
  case rateLimited                     // 429
  case serviceUnavailable              // 503 / 502 / 504
  case badRequest(message: String, details: [String])   // 400 with body
  case addressNotEligible(message: String)
  case unexpected(status: Int, body: String)
  case decoding(String)
}
extension USPSError {
  var title: String; var message: String; var hint: String?; var isRetryable: Bool
  var technicalDetails: String
}
```

User-facing copy:
- offline: "You're offline" / "PickupBar couldn't reach USPS." / hint "Check your connection and try again."
- invalidCredentials: "USPS rejected your API credentials" / "The Consumer Key or Secret is wrong, expired, or was revoked." / "Open Settings › Account to update them."
- forbidden: "Your USPS app can't access Carrier Pickup" / "USPS returned 403 Forbidden." / "In the USPS developer portal, make sure your app includes the Carrier Pickup (pickup) product, or contact USPS API Support."
- rateLimited: "Slow down a little" / "USPS is rate-limiting requests from this app." / "Wait a minute and try again."
- serviceUnavailable: "USPS is having trouble" / "The USPS API is temporarily unavailable." / "Try again in a few minutes."
- badRequest: "USPS couldn't schedule this pickup" / `message` / details listed.
- addressNotEligible: "This address isn't eligible for pickup" / message / "Double-check the address, or schedule at usps.com to see alternatives."
- unexpected: "Something unexpected happened" / "USPS returned status N." / "Copy the details and open an issue if this keeps happening."

### 4.4 Services

```swift
protocol USPSAPI: Sendable {
  func fetchToken(clientID: String, clientSecret: String) async throws -> OAuthToken
  func checkEligibility(_ address: PostalAddress, token: String) async throws -> PostalAddress  // standardized
  func schedulePickup(_ request: SchedulePickupRequest, token: String) async throws -> PickupConfirmation
}
struct OAuthToken: Codable, Equatable { var accessToken: String; var expiresAt: Date }

final class LiveUSPSClient: USPSAPI {
  init(baseURL: URL, session: URLSession = .shared)
}

actor TokenManager {
  init(api: USPSAPI, credentials: @Sendable () -> (id: String, secret: String)?, now: @Sendable () -> Date = Date.init)
  func validToken() async throws -> String     // refresh if missing or expiring within 60 s
  func invalidate()
}

struct KeychainStore {   // service "com.toddanglin.PickupBar", account "usps-consumer-key" / "usps-consumer-secret"
  func loadCredentials() throws -> (id: String, secret: String)?
  func saveCredentials(id: String, secret: String) throws
  func deleteCredentials() throws
}

final class SettingsStore: ObservableObject {   // @Published, persisted as JSON under key "settings.v1"
  var contact: PickupContact?
  var address: PostalAddress?          // standardized, only set after successful eligibility
  var defaultLocation: PackageLocation = .frontDoor
  var defaultInstructions: String = ""
  var dogPresent: Bool = false
  var defaultWeight: Double = 1
  var useTestEnvironment: Bool = false
  var lastConfirmation: PickupConfirmation?
}

struct PickupDateCalculator {
  static func availableDates(from now: Date, count: Int = 6, calendar: Calendar = Calendar(identifier: .gregorian)) -> [Date]
  // Rules: timezone America/Chicago; if now < 02:00 CT, today is a candidate; else start tomorrow.
  // Skip Sundays and USPS holidays (observed): New Year's Day, MLK Day (3rd Mon Jan), Presidents' Day (3rd Mon Feb),
  // Memorial Day (last Mon May), Juneteenth (Jun 19), Independence Day (Jul 4), Labor Day (1st Mon Sep),
  // Columbus Day (2nd Mon Oct), Veterans Day (Nov 11), Thanksgiving (4th Thu Nov), Christmas (Dec 25).
  // Observed: Sat holiday → Fri; Sun holiday → Mon.
  static func apiDateString(_ date: Date) -> String  // yyyy-MM-dd in America/Chicago
}
```

Base URL selection: `PICKUPBAR_BASE_URL` env var > TEM toggle > production.

### 4.5 Views (SwiftUI)

Popover window is fixed width 340 pt. Consistent 16 pt padding, `.regularMaterial`
style groups, SF Symbols, system fonts. Footer on every screen: gear button
(opens Settings) and a Quit item.

- **OnboardingView**: envelope hero, 3 numbered steps with link "Open USPS Developer Portal", two secure fields, "Verify & Save" (disabled until both non-empty, shows spinner, inline red error on failure).
- **AddressSetupView**: fields for contact + address; "Validate & Save" runs eligibility; shows standardized address on success then continues.
- **PickupFormView**:
  - Header "Schedule a pickup" + subtitle with address line.
  - Day chips (6) — `PickupDateCalculator.availableDates`.
  - Location `Picker` (menu) + optional instructions `TextField`.
  - Package rows: 6 types each with `Stepper` 0…50, showing count. Total shown.
  - Weight `TextField` (lb) with `.decimalPad`-like formatting, default from settings.
  - `Toggle` "No packages contain hazardous materials" — required.
  - Primary button "Schedule Pickup" enabled iff total ≥ 1, weight > 0, hazmat toggled on.
- **SchedulingView**: animated envelope (subtle pulse/float) + `ProgressView` + "Scheduling your pickup…".
- **ConfirmationView**: green checkmark, "Pickup scheduled", date in long form, confirmation number in monospaced large text, "Copy" button, primary "Schedule another pickup".
- **ErrorView**: warning icon, title/message/hint, "Copy details", primary "Try again" (if retryable) or "Open Settings".
- **SettingsView** (`Settings` scene, `TabView`): Account (masked key, status pill, Replace/Remove, TEM toggle), Address (same form as AddressSetupView), Defaults (location, instructions, dog present, weight), General (launch at login, version, GitHub link).

### 4.6 Attention / notifications

`AppState.needsAttention: Bool`. When true, `MenuBarExtra` label uses
`envelope.badge`. Set when `invalidCredentials` occurs; cleared when new
credentials verify. On first occurrence post a `UNUserNotification`
"PickupBar needs your USPS credentials" (request authorization lazily).

On launch, if credentials exist, `TokenManager.validToken()` runs in the
background to detect revoked credentials early.

## 5. Testing

Unit tests (XCTest, `PickupBarTests` target):
- Model encoding matches USPS wire JSON (contact array shape, package strings decode).
- `PickupDateCalculator`: 2 AM cutoff, Sunday skip, holiday and observed-holiday skip, count.
- `LiveUSPSClient` with `URLProtocol` mock: token success, 401 → invalidCredentials, 403 → forbidden, 429, 503, 400 body parsing, eligibility standardization, schedule success (both response shapes).
- `TokenManager`: caches, refreshes near expiry, invalidate forces refetch.
- `AppState` transitions with a `FakeUSPSAPI`.

Manual verification: `Scripts/mock-server.py` (stdlib only) implementing the three
endpoints; run app with `PICKUPBAR_BASE_URL=http://127.0.0.1:8787` and walk
every screen. ATS exception for localhost only (`NSAllowsLocalNetworking`).
